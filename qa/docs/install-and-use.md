QA 프로그램을 처음 쓰는 팀원을 위한 안내서예요. 설치부터 첫 시험, 결과 읽는 법, 문제가 생겼을 때 확인할 것까지 순서대로 적어 두었어요. 처음부터 끝까지 다 읽을 필요는 없고, 아래 **나에게 맞는 방법 고르기**에서 자기 상황에 맞는 부분만 따라 하면 돼요.

## 이 프로그램이 하는 일

정보지킴 서비스가 **정확하게 판정하는지, 데이터를 빠짐없이 처리하는지, 멈췄다가도 회복하는지**를 자동으로 채점해요.

1. 미리 정해 둔 입력(시험 문자, 이벤트)을 시험 대상에 넣어요.
2. 시험 대상이 돌려준 결과를 받아요.
3. 미리 정해 둔 정답이나 기준과 비교해서 통과/실패를 매겨요.
4. 결과를 HTML·JSON 보고서로 저장하고, 지난 기록과 함께 추이를 보여 줘요.

아직 실제 API·파이프라인이 완성되기 전이라, 기본값은 **연습용 대상**(가짜 판정기, 가짜 파이프라인)이에요. 연습용 대상에는 일부러 틀리는 규칙이 들어 있어서 **실패가 나오는 게 정상**이에요. 채점기가 틀린 결과를 제대로 잡아내는지 보는 용도예요.

시험은 세 영역으로 나뉘어 있어요.

| 영역 | 시험 | 한 줄 설명 |
|---|---|---|
| 서비스 | 빠른 점검(판정) · 데이터 처리 · 부하·응답 · 중단 후 복구 | 판정 API와 Kafka·Spark·MongoDB 파이프라인을 채점 |
| 앱 | 가짜 판정 서버 | 판정 API를 흉내 내는 서버에 앱을 붙여, 앱이 계약대로 요청하고 오류·지연에도 버티는지 확인 |
| QA 도구 | QA 도구 점검 | 이 QA 프로그램 자체가 정답을 맞게 계산하는지 확인 |

## 방법 1. 웹 대시보드 (설치 없음)

브라우저에서 아래 주소를 열면 끝이에요.

**https://seoloo.github.io/MLO2_3rd_Project/**

- `main` 브랜치에 코드가 올라갈 때마다 GitHub Actions가 시험을 돌리고 이 페이지를 자동으로 새로 만들어요.
- 서비스 영역과 QA 도구 영역으로 나뉘어 있고, 시험 종류마다 통과율 추이 막대가 있어요. 부하·복구 시험은 p95와 회복 시간 그래프도 있어요.
- 표에서 **실행 번호**를 누르면 그 실행의 상세 보고서가 열려요.
- 막대 위에 마우스를 올리면 그 실행의 시각, 값, 시험 대상이 나와요.
- "가짜" 표시가 붙은 기록은 연습용 대상으로 돌린 거라 실제 성능이 아니에요.

이 페이지는 **CI가 돌린 기록만** 보여 줘요. 각자 PC에서 돌린 기록은 각자의 PC에만 남아요.

## 방법 2. 배포 ZIP으로 설치하기

코드를 받을 필요 없이 실행 파일만 받아서 쓰는 방법이에요. 처음 한 번만 준비하면 다음부터는 더블클릭으로 켜져요.

### 0단계. 내 PC가 64비트 Windows인지 확인하기

**설정 → 시스템 → 정보**에서 **시스템 종류**가 "64비트 운영 체제, x64 기반 프로세서"인지 봐 주세요. 대부분의 노트북은 이미 이 상태예요.

### 1단계. .NET 10 Desktop Runtime 설치하기 (처음 한 번)

QA 앱은 .NET 10으로 만들었어요. 실행하려면 **.NET 10 Desktop Runtime(x64)** 이 PC에 있어야 해요. SDK가 아니라 **Runtime**만 있으면 돼요.

**가장 쉬운 방법:** 시작 메뉴에서 "터미널" 또는 "PowerShell"을 열고 아래 명령을 붙여 넣으세요.

```powershell
winget install Microsoft.DotNet.DesktopRuntime.10
```

**winget이 없다고 나오면:** [.NET 10 다운로드 페이지](https://dotnet.microsoft.com/download/dotnet/10.0)에서 **.NET Desktop Runtime** 항목의 **Windows x64** 설치 파일을 받아 실행하세요.

**잘 깔렸는지 확인:** 터미널을 새로 열고 아래 명령을 입력해요.

```powershell
dotnet --list-runtimes
```

`Microsoft.WindowsDesktop.App 10.`으로 시작하는 줄이 보이면 성공이에요.

> 런타임 없이 앱을 실행하면 "You must install or update .NET to run this application"처럼 .NET 설치를 안내하는 창이 떠요. 당황하지 말고 1단계를 하면 돼요.

### 2단계. ZIP 받기

[GitHub Releases 페이지](https://github.com/seoloo/MLO2_3rd_Project/releases)에서 가장 위에 있는(최신) 릴리스의 **`QA-windows-x64.zip`** 을 받으세요. QA 담당이 메신저로 직접 보내 준 경우에는 그 파일을 쓰면 돼요.

### 3단계. 압축 풀기 (중요)

1. 받은 ZIP을 오른쪽 클릭 → **모두 압축 풀기**를 눌러요.
2. 풀 위치는 **바탕 화면**이나 **문서** 폴더처럼 내가 쓸 수 있는 곳으로 정해요. 예: `C:\Users\내이름\Documents\QA`
3. 풀고 나면 폴더 안에 이렇게 있어야 해요.

```
QA-windows-x64/
├─ QaRunner.Desktop.exe        ← 실행 파일
├─ cases/                      ← 시험 문자·시나리오 (지우면 안 돼요)
│   ├─ rules.json
│   └─ pipeline/
├─ install-and-use.md          ← 이 안내서
└─ THIRD-PARTY-NOTICES.txt     ← 외부 라이브러리·이미지 라이선스
```

> **ZIP을 더블클릭해서 안에서 바로 exe를 실행하면 안 돼요.** 그러면 Windows가 임시 폴더에서 exe만 꺼내 실행해서 `cases` 폴더를 못 찾고, 보고서도 엉뚱한 곳에 저장돼요. 꼭 **전부 압축 풀기**를 한 뒤에 실행해 주세요.
>
> `C:\Program Files` 안에는 풀지 마세요. 그 폴더는 관리자 권한이 있어야 쓸 수 있어서 보고서 저장이 실패해요.

### 4단계. 실행하기

`QaRunner.Desktop.exe`를 더블클릭해요.

처음 실행할 때 파란 **Windows의 PC 보호** 창이 뜰 수 있어요. 코드 서명을 하지 않은 exe라서 그런 거예요. **추가 정보 → 실행**을 누르면 돼요. 한 번 실행하면 다음부터는 안 떠요.

### (선택) 바탕 화면 바로 가기 만들기

`QaRunner.Desktop.exe`를 오른쪽 클릭 → **추가 옵션 표시** → **보내기** → **바탕 화면에 바로 가기 만들기**를 누르면 돼요. exe 파일 자체를 바탕 화면으로 옮기면 `cases` 폴더와 떨어져서 안 되니, 꼭 **바로 가기**로 만들어 주세요.

### 새 버전으로 바꾸기

1. 새 ZIP을 받아서 **새 폴더에** 압축을 풀어요.
2. 예전 실행 기록을 이어서 보고 싶으면, 예전 폴더의 `reports` 폴더를 새 폴더로 복사해요.
3. 바로 가기를 만들어 뒀다면 새 exe로 다시 만들어요.

## 방법 3. 소스 코드로 실행하기

저장소를 받아서 직접 빌드하는 방법이에요. 내 API를 시험하거나(B) 파이프라인을 붙여야 하는 경우(C), QA 코드를 같이 고치는 경우에 써요. 장점은 **실행할 때마다 최신 코드를 자동으로 받는다**는 거예요.

### 1단계. 도구 설치하기 (처음 한 번)

터미널(PowerShell)에서 하나씩 실행하세요.

```powershell
winget install Git.Git
```

```powershell
winget install Microsoft.DotNet.SDK.10
```

설치가 끝나면 **터미널을 닫고 새로 열어서** 버전이 나오는지 확인해요. `dotnet --version`은 `10.0.`으로 시작해야 해요.

```powershell
git --version
```

```powershell
dotnet --version
```

### 2단계. 저장소 받기 (처음 한 번)

코드를 둘 폴더로 이동한 뒤 clone해요.

```powershell
git clone https://github.com/seoloo/MLO2_3rd_Project.git
```

### 3단계. 실행하기

탐색기에서 `MLO2_3rd_Project\qa\run-qa-desktop.cmd`를 **더블클릭**해요. 검은 창이 뜨고 아래 순서로 진행돼요.

| 순서 | 하는 일 | 참고 |
|---|---|---|
| 1/3 | 최신 코드 받기 (`git pull`) | 내가 고치던 파일이 있으면 안내만 하고 지금 코드로 계속해요 |
| 2/3 | 데스크탑 앱 빌드 | 처음에는 패키지를 받느라 1~2분 걸려요 |
| 3/3 | 앱 실행 | 창이 뜨면 끝이에요 |

- 앱이 이미 켜져 있으면 빌드가 안 돼서 "앱 창을 닫은 뒤 다시 실행해 주세요"가 나와요. 앱을 닫고 다시 더블클릭하세요.
- 빌드가 실패하면 오류 내용을 보여 주고 멈춰요. 그 창을 캡처해서 QA 담당에게 보내 주세요.
- 자주 쓴다면 `run-qa-desktop.cmd`의 바로 가기를 바탕 화면에 만들어 두면 편해요.

## 앱 사용법

### 화면 둘러보기

왼쪽 메뉴는 네 개예요.

| 메뉴 | 여기서 하는 일 |
|---|---|
| **홈** | 처음 사용하는 순서(4단계), 지금 할 일 배너, 통과율 요약, 영역별 시험 카드, 최근 실행 |
| **시험** | 시험 진행 상태와 결과. 항목을 골라 예상과 실제를 비교 |
| **기록** | **내 기록**: 이 PC에서 돌린 실행 목록 · **팀 공유**: 공유한 실행 목록 |
| **관리** | **시험 문자**: 시험에 쓰는 문자와 정답 · **AI 문자**: 준비 중 · **설정**: 파일·주소·보고서 위치 |

- 위쪽 제목 표시줄에 지금 위치(예: "정보지킴 QA / 시험 결과")가 나와요.
- 맨 아래 **상태 표시줄**에 지금 화면에서 할 일이나 진행 상황이 나와요.
- 버튼이나 입력칸에 마우스를 잠깐 올리면 설명 말풍선이 떠요.
- 왼쪽 아래 **사용 안내**나 **F1** 키를 누르면 안내 창이 열려요.

### 처음 5분: 빠른 점검 해 보기

1. 앱을 켜면 **홈**이 열려요. 위쪽 **처음 사용하는 순서**가 1단계(시험 고르기)에 있어요.
2. 초록 배너의 **빠른 점검 고르기**를 눌러요. 홈 아래쪽 **빠른 점검** 카드를 눌러도 같아요.
3. 오른쪽에서 **조건 시트**가 열려요. 시험 대상이 **연습용 대상**인지 확인하고 아래쪽 **시험 시작하기**를 눌러요.
4. 시험이 도는 동안 **진행 카드**가 떠요. 무엇을 하는 중인지, 몇 초 지났는지, 지금 단계(입력 보내기 → 결과 모으기 → 채점·보고서 저장)가 나와요. 맨 아래 상태 표시줄도 민트색으로 바뀌어요.
5. 약 10초 뒤 결과가 나와요. 맨 위 **완료 카드**에 "시험이 끝났어요"와 요약이 나오고, 상태 표시줄이 결과 색으로 바뀌어요.
6. 처음 몇 번은 말풍선이 첫 줄을 가리켜요. 그 줄을 눌러서 아래 **선택한 항목**에서 **예상 정답·기준**과 **실제 결과**를 비교해 보세요.
7. **보고서 열기**를 누르면 브라우저에서 HTML 보고서가 열려요.
8. 왼쪽 **기록** 메뉴에서 방금 실행을 다시 골라 보면 처음 사용하는 순서 4단계가 모두 끝나요.

### 시험 종류 고르기

홈의 **무엇을 점검할까요** 아래에 있는 영역 카드(서비스 · 앱 · QA 도구)로 영역을 바꿀 수 있어요. 카드마다 무엇을 점검하는지와 담당(A·B·C)이 적혀 있으니 내 담당 카드부터 눌러 보세요.

| 영역 카드 | 시험 카드 | 걸리는 시간 | 이럴 때 써요 |
|---|---|---|---|
| 서비스 | 빠른 점검 | 약 10초 | 판정이 정답과 같은지 빠르게 확인 |
| 서비스 | 데이터 처리 | 약 20초 | 중복·역순·지연 이벤트에서 Bronze·Silver·Gold·격리 건수가 맞는지 확인 |
| 서비스 | 부하·응답 | 기본 30초 | 계속 요청을 보내면서 API 응답 시간 p95, 오류율, Gold 반영 시간을 측정 |
| 서비스 | 중단 후 복구 | 기본 1분 | 처리를 15초 멈췄다 다시 켜고 따라잡는 시간을 측정 |
| 앱 | 가짜 판정 서버 | 켜 둔 동안 | 앱을 붙여 정상 판정·오류·지연 화면을 확인. [아래 안내](#앱을-가짜-판정-서버에-붙이기-a) 참고 |
| QA 도구 | QA 도구 점검 | 약 1초 | QA 프로그램을 고친 뒤 채점기·정답 계산이 그대로 맞는지 확인 |

카드를 누르면 오른쪽 조건 시트가 열려요. 조건 시트에서는 이런 걸 바꿀 수 있어요.

- **시험 대상:** 연습용 대상 / 내 판정 API (판정·부하 시험만)
- **시험 문자 파일 또는 시나리오 폴더:** 기본은 `cases/rules.json`, `cases/pipeline`
- **보내는 시간·초당 건수·중단 시간:** 부하·복구 시험만. 기본값은 화면에서 보여 주기 좋게 짧게 잡았어요. 실행안 기준은 부하 300초, 복구 120초·30초 중단이에요.
- **보고서 위치:** 기본은 앱이 있는 폴더의 `reports`

X나 시트 바깥을 누르면 닫혀요. 결과 화면의 **조건 바꾸기**로 다시 열 수 있어요.

### 결과 읽는 법

| 표시 | 뜻 |
|---|---|
| **통과** | 예상 정답과 같거나 기준을 만족했어요 |
| **불일치** | 예상과 다른 값이 나왔어요 |
| **기준 미달** | 측정값이 기준(예: p95 3초 이하)을 넘었어요 |
| **응답 없음** | 시험 대상이 결과를 못 돌려줬어요(연결 실패, 시간 초과 등). 판정이 틀린 것과는 달라요 |

시험이 끝나면 세 곳에서 알려 줘요.

- **완료 카드(결과 맨 위):** 요약과 **보고서 열기 · 다시 실행** 버튼. 연습용 대상이면 "연습용 대상" 표시가 붙어요.
- **상태 표시줄(맨 아래):** 모두 통과하면 초록, 다시 볼 항목이 있으면 주황, 응답 없음이나 오류가 있으면 빨강이에요. 오른쪽에 **보고서 열기 · 폴더 열기** 버튼이 붙어요.
- **말풍선:** 앱을 켠 뒤 처음 3번만, 결과 표의 첫 줄을 가리키며 다음에 뭘 누르면 되는지 알려 줘요.

> **연습용 대상에서 실패가 나오는 건 정상이에요.** 가짜 판정기는 "인증번호"라는 단어만 보고, 가짜 파이프라인은 격리를 하지 않아요. 채점기가 이런 틀린 결과를 실패로 잡아내는지 보는 거예요.

### 보고서와 기록 보기

- **보고서 열기:** 이번 실행의 HTML 보고서가 브라우저에서 열려요. 표는 `케이스 · 확인 항목 · 입력 · 정답 · 실제 · 결과`로 되어 있고, 실패한 항목이 위에 나와요.
- **전체 추이:** 지금까지 이 PC에서 돌린 기록을 모은 대시보드(`reports/dashboard.html`)가 열려요.
- **폴더 열기:** 보고서가 저장된 폴더가 탐색기로 열려요. 실행마다 `<실행 번호>.html`과 `<실행 번호>.json`이 생겨요. 실행 번호는 시작 시각이에요(예: `2026-10-29-143015`).
- **기록 › 내 기록:** 지난 실행을 고르면 그때 결과가 시험 화면에 다시 열려요. 완료 카드 제목이 "지난 실행 결과예요"로 바뀌어요.

### 설정 바꾸기

**관리 › 설정**에서 바꿀 수 있어요. 바꾼 값은 **지금 켜 둔 앱에서만** 쓰이고, 앱을 다시 켜면 기본값으로 돌아가요.

| 항목 | 설명 |
|---|---|
| 시험 문자 파일 | 판정 시험에 쓸 JSON 파일 |
| 판정 API 주소 | 내 API를 시험할 때 주소 (조건 시트와 같은 값) |
| 보고서 저장 폴더 | HTML·JSON 보고서와 기록이 쌓이는 곳 |
| 작업 폴더 | 경로의 기준이 되는 폴더 (읽기 전용) |
| 처음 사용하는 순서 | **처음부터 다시**를 누르면 홈의 4단계 안내와 말풍선이 처음 상태로 돌아가요 |

## 앱을 가짜 판정 서버에 붙이기 (A)

B의 판정 API가 아직 없어도 앱의 결과 화면과 오류 처리를 만들고 확인할 수 있어요. QA 앱이 **판정 API(`POST /checks`)를 흉내 내는 서버**를 이 PC에 켜 주고, 앱은 API 주소만 그 서버로 바꾸면 돼요. 서버는 앱이 보낸 요청이 [연결 계약 3장](https://github.com/seoloo/MLO2_3rd_Project/blob/main/docs/contract.md#3-판정-api-b)과 같은 형식인지도 함께 확인해 줘요.

### 순서

1. QA 앱 홈의 **무엇을 점검할까요** 아래에서 **앱** 영역 카드를 눌러요.
2. 포트는 보통 `8000` 그대로 두면 돼요. B의 서버가 이미 8000을 쓰고 있으면 `8010`처럼 바꿔요.
3. **응답 방식**은 처음에는 **자동 판정**으로 두세요. 문자 내용에 따라 고위험·주의·신호 미발견·판단 보류가 나와요.
4. **서버 켜기**를 누르면 **앱에 넣을 주소**가 나와요. 아래 표에서 내 상황에 맞는 주소를 앱의 API 주소로 넣어 주세요. 끝에 `/checks`는 붙이지 않아요.
5. 앱에서 문자를 넣고 판정을 요청해요. 오른쪽 **받은 요청** 목록에 바로 한 줄씩 쌓여요.
6. 응답 방식을 **서버 오류 500**, **12초 늦은 응답**처럼 바꿔 가며 앱 화면을 확인해요. 켜 둔 채로 바꿔도 다음 요청부터 바로 적용돼요. 카드 안의 **앱에서 확인할 것**에 무엇을 봐야 하는지 적혀 있어요.
7. 다 봤으면 **끄고 결과 보기**를 눌러요. 받은 요청마다 계약과 같은지 채점한 결과가 나오고, 보고서도 **앱 영역** 기록으로 저장돼요.

| 앱을 띄운 곳 | 앱에 넣을 주소 |
|---|---|
| 웹 브라우저(Expo 웹), iOS 시뮬레이터 | `http://127.0.0.1:8000` |
| Android 에뮬레이터 | `http://10.0.2.2:8000` (에뮬레이터에서는 이 주소가 내 PC를 가리켜요) |
| USB로 연결한 Android 휴대폰 | 먼저 `adb reverse tcp:8000 tcp:8000`을 실행하고 `http://127.0.0.1:8000` |
| Expo Go로 띄운 실제 휴대폰 (같은 Wi-Fi) | **같은 Wi-Fi의 휴대폰에서도 접속 허용**을 켠 뒤 서버를 켜고, 화면에 나온 `http://192.168.x.x:8000` 주소 |

- **같은 Wi-Fi 허용**을 켜면 처음에 Windows 방화벽이 허용할지 물어봐요. 같은 네트워크의 다른 기기도 접속할 수 있으니 카페 같은 공용 Wi-Fi에서는 켜지 마세요.
- 문자 끝에 `#500`, `#slow`, `#timeout`처럼 표시를 붙이면 **그 요청만** 다른 응답을 받아요. 응답 방식 목록 오른쪽에 표시가 적혀 있어요. 응답 방식을 매번 바꾸지 않고 한 화면에서 여러 경우를 확인할 때 편해요.
- **자동 판정**은 "인증번호", "링크" 같은 단어 몇 개만 보는 화면 확인용 규칙이에요. 실제 판정 품질과는 관계없어요.
- 서버를 켜 둔 동안 요청이 한 건도 없으면, 끌 때 보고서를 만들지 않고 주소를 확인해 달라고 알려 줘요.

### 꼭 확인해 볼 응답 방식

| 응답 방식 (표시) | 앱에서 확인할 것 |
|---|---|
| 자동 판정 (`#auto`) | 한글 판정과 근거·대응 안내가 함께 보이는지 |
| 근거 없는 판정 (`#noevidence`) | 근거·안내가 없어도 화면이 깨지지 않는지 |
| 아주 긴 근거·안내 (`#long`) | 긴 글이 잘리지 않고 스크롤로 다 읽히는지, 버튼이 밀려나지 않는지 |
| 모르는 판정 코드 (`#unknown`) | 영문 코드를 그대로 보여 주거나 앱이 멈추지 않는지 |
| 3초 늦은 응답 (`#slow`) | 로딩 표시가 보이는지, 버튼을 여러 번 눌러도 요청이 한 번만 가는지 (받은 요청 건수로 확인) |
| 12초 늦은 응답 (`#timeout`) | 10초가 지나면 기다림을 멈추고 ‘시스템 실패’와 다시 시도 방법이 보이는지 |
| 깨진 응답 (`#broken`) | 응답을 읽지 못해도 앱이 멈추지 않는지 |
| 서버 오류 500 (`#500`) · 일시 중단 503 (`#503`) | 판정 결과와 분명히 구분되는 ‘시스템 실패’ 안내가 나오는지 |

콘솔로도 켤 수 있어요. 맥에서 앱을 개발한다면 이 방법을 쓰면 돼요. `qa` 폴더에서 실행하고, 끝낼 때는 Enter나 Ctrl+C를 누르세요.

```bash
dotnet run --project src/QaRunner -- --suite mockapi
```

```bash
dotnet run --project src/QaRunner -- --suite mockapi --port 8010 --scenario timeout --allow-lan
```

## 내 판정 API 시험하기 (B)

FastAPI 판정 서버를 띄워 두고, QA 앱이 그 API에 문자를 보내 채점하게 하는 방법이에요. [방법 3](#방법-3-소스-코드로-실행하기)으로 앱을 켜는 걸 추천해요.

### API가 맞춰야 할 형식

[연결 계약 초안(docs/contract.md)](https://github.com/seoloo/MLO2_3rd_Project/blob/main/docs/contract.md) 3장 기준이에요.

| 구분 | 내용 |
|---|---|
| 요청 | `POST {API 주소}/checks`, 본문 `{ "message": "문자 내용" }` |
| 응답 | `200 OK`, 본문에 `verdict`가 있어야 해요. `HIGH_RISK`·`CAUTION`·`NO_SIGNAL`·`UNDECIDED` 같은 영문 코드나 `고위험`·`주의`·`신호 미발견`·`판단 보류` 같은 한글 모두 돼요 |
| 시간 제한 | 10초 안에 응답해야 해요 |

QA는 **예상 정답을 API에 보내지 않아요.** 문자만 보내고, 정답 비교는 QA 안에서만 해요.

### 순서

1. 내 PC에서 판정 서버를 켜요. 예: `uvicorn main:app --port 8000`
2. 브라우저에서 `http://localhost:8000/docs`가 열리는지 먼저 확인해요. 여기서 안 열리면 QA에서도 연결이 안 돼요.
3. QA 앱 홈에서 **빠른 점검** 카드를 눌러 조건 시트를 열어요.
4. 시험 대상에서 **내 판정 API**를 고르고 주소에 `http://localhost:8000`을 넣어요. 끝에 `/checks`는 붙이지 않아요.
5. **시험 시작하기**를 눌러요.

- 주소가 비어 있거나 `http://`·`https://`로 시작하지 않으면 실행하지 않고 시트 안에서 알려 줘요.
- 결과가 **응답 없음**으로 나오면 항목을 골라 오류 내용을 보세요. 연결 거부(서버 꺼짐), 404(경로 다름), 시간 초과(10초 넘음), `verdict` 없음(응답 형식 다름) 중 하나인 경우가 많아요.
- **부하·응답** 카드도 같은 방법으로 내 API를 대상으로 돌릴 수 있어요. API 응답 시간 p95가 3초 이하이고 오류율이 0%인지 확인해요.

## 콘솔 프로그램 (C)

실제 Kafka·MongoDB·Spark를 대상으로 하는 시험은 데스크탑 앱이 아니라 콘솔 프로그램으로 돌려요. [방법 3](#방법-3-소스-코드로-실행하기)으로 저장소를 받은 뒤 `qa` 폴더에서 실행하세요.

```powershell
cd MLO2_3rd_Project\qa
```

연습용 대상으로 먼저 동작을 확인해요.

```powershell
dotnet run --project src/QaRunner -- --suite pipeline
```

시험 환경(docker-compose)을 띄운 뒤 실제 파이프라인을 대상으로 돌려요.

```powershell
dotnet run --project src/QaRunner -- --suite pipeline --kafka localhost:9092 --mongo mongodb://localhost:27017
```

짧은 복구 시험은 이렇게 돌려요. docker 명령을 쓸 수 있는 PC에서 해야 해요.

```powershell
dotnet run --project src/QaRunner -- --suite recovery --duration 60 --stop-seconds 15 --kafka localhost:9092 --mongo mongodb://localhost:27017
```

- 끝나면 종료 코드로 결과를 알려 줘요. `0` 모두 통과, `1` 실패 있음, `2` 시작조차 못 함(옵션·파일·연결 문제)이에요.
- 토픽 이름(`--kafka-topic`, 기본 `scan-events`), DB 이름(`--mongo-db`, 기본 `jeongbo`), Spark 컨테이너 이름(`--spark-container`, 기본 `spark`)을 바꿀 수 있어요.
- 다른 데이터가 섞이면 Gold 집계가 틀어지니 **시험 전용 환경**에서 돌려 주세요.
- EC2에 붙일 때 `--mongo`에 비밀번호가 든 연결 문자열을 넣으면 셸 기록이나 CI 로그에 남아요. 단톡방·이슈에 그대로 붙이지 말고, 먼저 [AWS·EC2 보안 체크리스트](https://github.com/seoloo/MLO2_3rd_Project/blob/main/infra/README.md#awsec2-보안-체크리스트)를 한 번 훑어 주세요.
- 옵션 전체와 처음 연결할 때 확인 순서는 [QA README의 실제 시스템에 연결하기](https://github.com/seoloo/MLO2_3rd_Project/blob/main/qa/README.md#실제-시스템에-연결하기)를 봐 주세요.

## 문제가 생겼을 때

| 증상 | 원인과 해결 |
|---|---|
| exe를 눌렀더니 ".NET을 설치(install)하라"는 창이 떠요 | .NET 10 Desktop Runtime이 없어요. [방법 2의 1단계](#1단계-net-10-desktop-runtime-설치하기-처음-한-번)를 해 주세요 |
| 파란 "Windows의 PC 보호" 창이 떠요 | 서명하지 않은 exe라서 그래요. **추가 정보 → 실행**을 누르세요 |
| "아직 시험을 시작하지 못했어요. Could not find file ... rules.json" 오류가 나요 | ZIP 안에서 바로 실행했거나 `cases` 폴더가 exe 옆에 없어요. ZIP을 **전부 압축 풀기**한 뒤 그 폴더의 exe를 실행하세요 |
| 보고서 저장이 안 돼요 | `Program Files`처럼 쓰기 권한이 없는 폴더에 풀었을 수 있어요. 문서 폴더 같은 곳으로 옮겨 주세요 |
| 결과가 실패투성이예요 | 연습용 대상이면 정상이에요. 완료 카드에 "연습용 대상" 표시가 있는지 보세요 |
| 내 API인데 전부 "응답 없음"이에요 | 서버가 켜져 있는지, 주소가 `http://localhost:8000`처럼 맞는지, `/checks` 경로와 응답의 `verdict` 필드가 있는지 확인하세요 |
| `run-qa-desktop.cmd`에서 "앱 창을 닫은 뒤 다시 실행해 주세요"가 나와요 | QA 앱이 켜져 있어서 빌드를 못 해요. 앱을 닫고 다시 더블클릭하세요 |
| `run-qa-desktop.cmd`에서 "최신 코드를 받지 못했습니다"가 나와요 | 내가 고치던 파일이 있거나 다른 브랜치에 있어서 그래요. 지금 코드로는 계속 실행돼요. 최신 코드가 필요하면 `git status`로 상태를 확인하세요 |
| `dotnet`이나 `git`을 찾을 수 없다고 나와요 | 설치 직후에는 터미널을 **닫고 새로 열어야** 인식돼요. 그래도 안 되면 PC를 한 번 다시 시작해 보세요 |
| 화면 글자가 작거나 잘려요 | 창 크기에 따라 본문 배율이 75~100%로 자동 조정돼요. 창을 키우거나 최대화해 보세요. 오른쪽 아래에 지금 배율이 나와요 |
| 가짜 판정 서버를 켜면 "포트를 열지 못했어요"가 나와요 | 판정 API 같은 다른 프로그램이 그 포트를 쓰고 있어요. 포트를 `8010`처럼 바꾸고, 앱의 주소도 같은 포트로 바꿔 주세요 |
| 앱에서 요청했는데 받은 요청 목록이 비어 있어요 | 주소를 확인하세요. Android 에뮬레이터는 `127.0.0.1`이 아니라 `10.0.2.2`, 실제 휴대폰은 같은 Wi-Fi 허용을 켠 뒤 화면에 나온 `192.168.x.x` 주소예요. Android에서 `http://` 주소가 막히면 개발용 설정에서 평문 HTTP(cleartext)를 허용해야 해요 |
| 다른 팀원이 돌린 결과를 보고 싶어요 | 각자 PC 기록은 그 PC에만 있어요. 팀이 함께 보는 결과는 [웹 대시보드](#방법-1-웹-대시보드-설치-없음)를 봐 주세요 |

## 도움을 요청할 때

QA 담당에게 아래를 같이 보내 주면 원인을 빨리 찾을 수 있어요.

1. **무엇을 하다가** 생겼는지 (예: 빠른 점검 카드 → 내 판정 API → 시험 시작하기)
2. **화면 캡처** (상태 표시줄의 메시지가 보이게)
3. **설치 방법** (방법 2 ZIP인지, 방법 3 소스인지)
4. 결과가 이상하면 그 실행의 **JSON 보고서** (`reports/<실행 번호>.json`, **폴더 열기**로 찾을 수 있어요)

보고서에는 시험용으로 만든 문자만 들어 있어요. 실제 사용자 문자나 개인정보는 시험 케이스에 넣지 말아 주세요.
