# 정보지킴 자동화 QA 러너

입력값과 정답을 파일에 적어 두면, 프로그램이 입력값을 판정 대상에 넣고 돌아온 결과를 정답과 비교해 채점하는 C# 콘솔 프로그램입니다. 실행할 때마다 결과를 보고서 파일로 남깁니다.

## 진행 상황

| 단계 | 내용 | 상태 |
|---|---|---|
| ① 스켈레톤 | 입력값 파일 → 가짜 판정 대상 → 채점 → 콘솔 출력·종료 코드 | 완료 |
| ② 결과 저장·HTML 보고서 | 실행 번호별 JSON·HTML 보고서 저장 | 완료 |
| ③ 실제 API 연결 | 가짜 판정 대상 대신 FastAPI 호출 (B의 API 필요) | 다음 |
| ④ 파이프라인 시험 | Kafka에 중복·역순·지연 주입, Bronze·Silver·Gold 비교 (C의 파이프라인 필요) | 예정 |
| ⑤ 부하·복구 시험 | 5건/초 × 5분 발행, Spark 중단·재가동, p95·회복 시간 측정 | 예정 |
| ⑥ 자동 실행·CI | docker-compose 서비스 추가, CI에서 종료 코드로 판정 | 예정 |
| ⑦ 실행 기록 대시보드 | 저장된 보고서를 모아 추이 표시 | 선택 |

## 흐름

```
입력값 파일 ──(문자)──▶ 판정 대상 ──(실제 판정)──▶ 채점 ──▶ 결과 (콘솔 · 보고서 · 종료 코드)
     └──────────────(정답)─────────────────────────┘
```

- 정답은 판정 대상을 거치지 않고 채점 단계로 바로 갑니다. 시스템이 틀려도 정답은 오염되지 않습니다.
- 판정 대상은 바꿔 끼울 수 있습니다. 지금은 가짜(`FakeVerdictService`)이고, FastAPI가 준비되면 그 부분만 바꿉니다.

## 빠른 시작

### 1. .NET 10 SDK 설치 (처음 한 번)

```bash
winget install Microsoft.DotNet.SDK.10
```

설치 후 터미널을 새로 열고 버전을 확인합니다. `10.0.`으로 시작하면 됩니다.

```bash
dotnet --version
```

### 2. 실행

명령은 모두 `qa/` 폴더에서 실행합니다.

```bash
dotnet run --project src/QaRunner
```

지금은 가짜 판정 대상이 "인증번호"라는 단어만 보고 판정하므로 4건 중 2건이 실패합니다. 채점기가 틀린 판정을 잡아내는지 확인하려고 일부러 그렇게 둔 것입니다.

### 3. 테스트

QA 러너 자체가 올바르게 동작하는지 확인합니다.

```bash
dotnet test
```

## 옵션

옵션은 `--` 뒤에 붙입니다. 생략하면 기본값을 씁니다.

```bash
dotnet run --project src/QaRunner -- --cases cases/rules.json --reports reports
```

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `--cases` | 읽을 입력값 파일 | `cases/rules.json` |
| `--reports` | 보고서를 저장할 폴더 | `reports` |

## 시험 케이스 작성법

### 판정 시험 (`cases/rules.json`)

케이스 하나가 한 줄입니다. 줄을 추가하면 코드를 고치지 않아도 채점 대상이 늘어납니다.

```json
[
  { "caseId": "R-001", "message": "[택배] 상담원에게 인증번호를 알려주세요", "expectedVerdict": "고위험" },
  { "caseId": "R-005", "message": "입력할 문자", "expectedVerdict": "주의" }
]
```

| 키 | 뜻 | 규칙 |
|---|---|---|
| `caseId` | 케이스 번호 | 겹치지 않게. 실패했을 때 이 번호로 찾음 |
| `message` | 판정 대상에 넣을 문자 (입력값) | 실제 사용자 문자가 아닌 시험용으로 만든 문자 |
| `expectedVerdict` | 정답 판정 | `고위험`, `주의`, `신호 미발견`, `판단 보류` 중 하나 |

정답 라벨은 A와 B가 함께 정하고 PR로 검토받아 넣습니다.

### 파이프라인 시나리오

④단계에서 추가합니다. 이벤트와 함께 중복·역순·지연·재시작 조건을 적는 형식이 됩니다.

## 보고서

실행할 때마다 보고서 폴더(기본 `reports/`)에 실행 번호로 파일 두 개가 생깁니다. 실행 번호는 시작 시각입니다(예: `2026-10-26-143015`). 이 폴더는 git에 올라가지 않습니다.

| 파일 | 용도 |
|---|---|
| `<실행 번호>.html` | 브라우저로 여는 보고서. 전체·통과·실패·통과율과 케이스별 결과 |
| `<실행 번호>.json` | 같은 내용을 다른 프로그램(대시보드, CI)이 읽는 용도 |

보고서 읽는 법:

- 실패한 케이스가 표의 위쪽에 먼저 나옵니다.
- 가짜 판정 대상으로 실행한 보고서에는 "실제 판정 규칙의 성능이 아닙니다"라는 안내가 붙습니다.

프로그램이 끝날 때 돌려주는 종료 코드는 CI가 성공·실패를 판단하는 데 씁니다.

| 종료 코드 | 뜻 |
|---|---|
| `0` | 모든 케이스 통과 |
| `1` | 실패한 케이스가 하나 이상 있음 |

## 폴더 구조

```
qa/
├─ cases/rules.json                 입력값 + 정답
├─ src/QaRunner/
│   ├─ Program.cs                    실행 순서 연결 (읽기 → 판정 → 채점 → 출력 → 저장)
│   ├─ CommandLineOptions.cs         --cases, --reports 옵션 읽기
│   ├─ TestCaseLoader.cs             입력값 파일 읽기
│   ├─ VerdictChecker.cs             채점기: 정답 vs 실제 판정
│   ├─ Models/
│   │   ├─ TestCase.cs               시험 케이스 한 건 (케이스 번호, 문자, 정답)
│   │   ├─ TestResult.cs             채점 결과 한 건 (문자, 정답, 실제 판정, 통과 여부)
│   │   └─ TestRun.cs                한 번 실행한 기록 (실행 번호, 시각, 결과 목록, 통과율)
│   ├─ Verdicts/
│   │   ├─ IVerdictService.cs        판정 대상이 갖춰야 할 모양
│   │   └─ FakeVerdictService.cs     임시 가짜 판정 대상
│   └─ Reports/
│       ├─ JsonReportWriter.cs       JSON 보고서 저장
│       └─ HtmlReportWriter.cs       HTML 보고서 저장
└─ tests/QaRunner.Tests/             QA 러너 자체의 테스트
```

## 확장 방법

### 판정 대상을 실제 API로 바꾸기 (③단계)

1. `src/QaRunner/Verdicts/`에 `IVerdictService`를 구현한 클래스를 추가합니다. 예: `ApiVerdictService`가 FastAPI에 문자를 보내고 판정을 받아 돌려줌
2. `Program.cs`의 "2. 판정 대상 정하기" 줄에서 `new FakeVerdictService()`를 새 클래스로 바꿉니다.
3. 채점기, 보고서 등 나머지 코드는 고치지 않습니다.

### 보고서에 항목 추가하기

1. `Models/TestRun.cs`(실행 전체) 또는 `Models/TestResult.cs`(케이스 한 건)에 속성을 추가합니다. JSON 보고서에는 자동으로 들어갑니다.
2. HTML 보고서에 보여 주려면 `Reports/HtmlReportWriter.cs`의 `BuildHtml`을 고칩니다.

### 코드를 고칠 때 지킬 것

- 이름은 무엇인지 바로 알 수 있게 짓습니다. 예: `testCase`, `failedCount` (한 글자 변수, 줄임말 쓰지 않기)
- 클래스, 함수, 중요한 변수에는 무엇이고 왜 있는지 한국어 주석을 답니다.
- 동작을 바꾸면 `tests/QaRunner.Tests/`에 테스트를 추가하고 `dotnet test`가 통과하는지 확인합니다.
- 코드, 옵션, 파일이 바뀌면 이 README도 같은 커밋에서 고칩니다.
