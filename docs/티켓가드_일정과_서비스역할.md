## 이미지의 핵심 경로

0.2 연결 계약 → 3.1/3.2 환경·토픽 → 2.3 수집 API → 3.4 Bronze 수집 → 2.4 판정 → 1.4 상황판 → 4.5 부하·복구 → 0.4 시연임. 곁가지는 3.6 S3·재생 → 4.7 새 유형 평가임.

## 현재 사이트의 성격

고객은 공연 선택·가입/로그인·대기·좌석·예매·취소를 사용함. 로그는 관리자만 별도로 확인함. 이 Django 서비스는 공격·부하·추적 검증의 대상과 데이터 원천이며, 탐지 결과를 꾸며 표시하지 않음. 실제 결제·입장권 발급은 없음.

## 기술 역할의 차이

이미지는 React Native/Expo(앱), FastAPI/Spark(백엔드), 인프라 환경/Kafka/DB/S3(인프라), 별도 QA를 기준으로 함. 사용자가 요청한 Django는 임시 대상 서비스의 실행 프레임워크임. Django가 전체 필수 기술을 구현한 것으로 계산하지 않음. 좌석 점유는 현재 서비스 DB 트랜잭션으로 보장하며 Redis는 미연결임.

현재 실행 방식: 예매 대상 사이트는 Python 가상환경으로 실행하며 AWS 배포를 준비함. 이미지의 인프라 기술 선택과 구분함.
