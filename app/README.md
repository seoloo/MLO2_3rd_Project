# app — React Native 예매 앱 (담당: A)

공연을 고르고 대기열 → 좌석 → 결제(→ 추가 확인)까지 예매하는 화면과, 예매하는 동안 화면 이동·클릭을 기록해 보내는 **행동 기록기**, 운영자 상황판과 기획사 리포트를 만드는 곳입니다. 앱은 하나이고, 로그인한 계정의 역할(예매자·운영자·기획사)에 따라 보이는 화면만 다릅니다.

## 여기에 둘 것

- React Native + TypeScript 앱
  - 예매자: 공연 → 대기열 → 좌석 → 결제 → 추가 확인 (휴대폰)
  - 운영자: 실시간 상황판 · 세션 상세 · 조치 (태블릿 · PC 웹)
  - 기획사: 판매 결과 리포트 (PC 웹 · 태블릿)
- 행동 기록기: 화면 이동·클릭을 1초 단위로 모아 수집 API로 보내는 모듈
- Expo 웹 빌드 (PC 화면과 봇 C의 대상)
- 이 폴더만의 실행 방법과 테스트

## 지켜야 할 계약

[docs/contract.md](../docs/contract.md)의 아래 장을 따릅니다.

| 장 | 내용 |
|---|---|
| 2. 판정 값 | API는 영문 코드(`NORMAL`·`WATCH`·`VERIFY`·`HOLD`)를 주고, 화면에는 한글(정상·관찰·추가 확인·보류)로 보여 줌. 사람을 "매크로 사용자"로 단정하는 표현은 쓰지 않음 |
| 3. 예매 API | 대기열·좌석 점유(5분)·결제·추가 확인. 결제 응답이 `VERIFY_REQUIRED`면 좌석을 유지한 채 본인 확인 화면, `ON_HOLD`면 운영자 검토 안내 |
| 4. 수집 API와 행동 이벤트 | `POST /events`에 1초 묶음으로. 클라이언트 이벤트는 `origin: "client"`, 이름·전화번호는 넣지 않고 해시만 |
| 5. 판정 조회 API | 운영자 상황판의 세션 판정과 근거(`rules`, `ruleVersion`) |
| 7-2. `gold_live_metrics`, `gold_reports` | 상황판의 초 단위 집계와 기획사 리포트 |

## QA와의 관계

- 백엔드가 나오기 전에는 QA 데스크탑 앱의 **홈 › 앱 영역 카드 › 가짜 예매·판정 서버**에 앱을 붙여 개발할 수 있습니다. 대기열·좌석 점유·결제·추가 확인·이벤트 수집·판정 조회를 계약대로 흉내 내고, 항상 추가 확인·보류·긴 대기열·이미 점유된 좌석·매진·점유 시간 끝남·판정 지연·500·503·12초 늦은 응답·깨진 응답을 골라 받아 볼 수 있습니다. 앱이 보낸 요청이 계약과 같은지도 기록합니다.
- Android 에뮬레이터는 `http://10.0.2.2:8000`을 씁니다. 따라 하기: [설치·사용 안내](../qa/docs/install-and-use.md#앱을-가짜-예매판정-서버에-붙이기-a)
- QA의 봇 C는 Playwright로 **우리 앱의 Expo 웹 화면**을 직접 누르는 봇입니다. 버튼에 안정적인 이름(`testID` 등)을 달아 두면 QA가 붙이기 쉽습니다.
- 시연 화면 캡처가 필요하면 QA 데스크탑 앱의 캡처 모드를 쓸 수 있습니다 ([qa/README.md](../qa/README.md)).

## 작업 브랜치

`main`에서 `feature/app-...` 브랜치를 만들어 작업하고 PR로 합칩니다. 예: `feature/app-seat-select`


## Django 공용 예매 대상 사이트

`ticketing-site/`에 브라우저 기반 예매 대상 사이트를 추가했습니다. 회원가입·로그인·공연·좌석·5분 점유·승인 시뮬레이션·취소와 관리자 전용 기록을 제공합니다. Windows Python 가상환경과 EC2용 Docker/Nginx/Gunicorn/PostgreSQL 구성을 포함합니다.

- [로컬 실행·현재 기능](ticketing-site/README.md)
- [AWS 배포 안내](ticketing-site/AWS_DEPLOY.md)
- [현재 대상 사이트 이벤트 규격](ticketing-site/EVENT_CONTRACT.md)

이 사이트는 QA 입력을 발생시키는 별도 Django 대상 서비스입니다. 위 React Native/Expo 앱이나 FastAPI·Redis·Kafka·Spark 판정 계층이 완성된 것을 의미하지 않습니다. 현재 경로·이벤트는 `docs/contract.md`와 동일하지 않으므로 기존 QA 계약에 직접 호환된다고 가정하지 말고 연결 어댑터를 합의해야 합니다. 실제 PG 결제·추가 인증·매크로 판정은 연결하지 않았습니다.
